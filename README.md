# ICC CE × WPS 墨迹同步插件

目标：WPS 打开 .doc(x)/.pdf 时，鼠标模式下页面移动，白板上的批注笔迹跟着页面一起走。

当前阶段：**控制模式可用** —— 由 ICC 浮动栏按钮/热键命令 WPS 翻页（`WM_MOUSEWHEEL` 直接发给 WPS 文档子窗口），
所以位移量是我们自己发出的格数算出来的，不依赖"看画面猜"。实测来回一趟 **逐像素 0.000% 差异**。

抓到画面只能做到 ~6 帧/秒，快速滚轮/拖滚动条/手型拖动跟不住，所以主路径改成"我们控制滚动"；
抓帧退化成**复核**：确认 WPS 真的滚了、滚了多少，没滚（到顶/到底）就把墨迹退回去。

## 怎么用

1. 打开 WPS 里的文档。ICC 在**鼠标模式或画笔模式**下都会响应（批注过程中也能翻页）。
2. ICC 浮动栏出现：`跟随` / `上1` / `下1` / `上6` / `下6`（+ 调试控件打开时还有 `归位` / `打样` + 一行状态）。
   - 每个按钮都是**上图标、下文字**，和原生 `鼠标/批注/白板` 同一套观感。
     插件项容器高度被宿主压到 27px（原生那条 44px），所以图标 16×16 + 字号 10.5 / 行高 12 刚好塞满，
     实测按钮 42×27，文字完整不裁。
   - `上1` `下1` = 翻 1 格（约 1 行，60px @300%）；`上6` `下6` = 翻 6 格（约 1/4 屏）。方向按"你看到的画面往哪走"标的。
   - `跟随` 关掉时按钮变暗（0.45 不透明度），鼠标悬停有说明；同时**整排翻页按钮收起**
     （`上1`/`下1` + 打开"显示 6 行滚动按钮"时的 `上6`/`下6`），只剩 `跟随` 自己；
     归位 / 打样 / 状态文字属于调试控件，不受影响。热键仍然在（`Ctrl+Alt+F` 开回来即可），
     但跟随关着时按翻页热键会被忽略（日志 `跟随已关闭，忽略`）。
   - `打样` = 注入 3 条合成笔迹，用来肉眼验证/试手。
   - **只有插件自己的翻页按钮/热键才带墨迹**。用鼠标滚轮、手型拖动、拖滚动条滚动页面时，墨迹**一律不动**
     （日志 `外部滚动，不跟`）。以前会"追"这些滚动，但抓帧量不准，追出来的位移完全是错的。
3. 演示前想清爽一点：**设置 → 插件设置 → WPS 墨迹同步 设置** 里有三个开关：
   - **显示调试控件**：关掉后浮动栏只剩 `跟随` + 四个翻页按钮（`归位`/`打样`/状态文字隐藏，热键仍然可用）。
   - **显示插件按钮**：`始终` / `仅当 WPS 运行时` / `关闭`。
     - `仅当 WPS 运行时` —— 每 500ms 探一次 WPS 文档窗口；WPS 一关（或最小化），
       抓帧线程立刻停（日志 `WPS 已退出 → 插件停止` + `follower stopped（不再抓帧）`），重新打开 WPS 自动接回。
     - `关闭` —— 工具栏整块收起、追随器停、热键全部注销（`hotkeys 已注销`），插件完全不跑。
     - 收起是"连底壳一起收"：宿主给插件项的圆角容器不会跟着我们的面板 Collapsed 一起消失（会留一条很瘦的底儿），
       所以顺着可视树把只含我们一个孩子的包装层（`StackPanel < Border`）一并 Collapsed，碰到多孩子的排列区就停手，
       绝不牵连原生的 鼠标/批注/白板/工具/隐藏。宿主挂载后会把视图 Visibility 改回 Visible，
       因此在 `Loaded` 之后再压一次，并用 `IsVisibleChanged` 立刻反弹（不用等 500ms 定时器）。
   - **是否显示 6 行滚动按钮**：`否` 时只剩 `跟随` / `上1` / `下1`，热键 `Ctrl+Alt+PgUp/PgDn` 照旧可用。
   同一个页面里还有：`打开日志目录`、`复制日志路径`、`复制今日日志`、内联查看今天最近 200 行日志。
   三个开关都存在插件目录自己的 `settings.ini`（宿主那份要正常退出才落盘，部署是强杀，存不住）。
4. 热键（讲课时手不用离开笔）：

| 热键 | 作用 |
|---|---|
| `Ctrl+Alt+↑` / `Ctrl+Alt+↓` | 翻 1 格 |
| `Ctrl+Alt+PgUp` / `Ctrl+Alt+PgDn` | 翻 6 格 |
| `Ctrl+Alt+R` | 归位（墨迹平移量清零） |
| `Ctrl+Alt+F` | 跟随开关 |
| `Ctrl+Alt+K` | 打样（注入 3 条正弦笔迹，用来肉眼验收） |
| `Ctrl+Alt+M` | 在日志里打一行 MARK（汇报 bug 时按一下，我据此定位） |
| `Ctrl+Alt+D` | 调试控件开关（等同设置页里那个勾） |

状态区示例：

```
二选一复核: 预期=-360px 滚了=1.000 没滚=0.892 → 判定 已滚   | Δ=(0,-360) n=2
```

前半是跟随器（本次按下命令滚 360px，复核结果），后半是墨迹累计位移。

## 原理

### 为什么要反过来控制

WPS 是 Qt5 + Skia 自绘：Win32 滚动条（`GetScrollInfo`）和 UIA `ScrollPattern` 都拿不到滚动量（已实测排除）。
只能抓画面（`PrintWindow(..., PW_RENDERFULLCONTENT)`，34ms）再做 2D 块匹配（~110ms）→ 一帧 ~148ms ≈ 6.7 帧/秒。
快速滚轮的帧间位移就冲到 300~400px（逼近搜索上限），拖滚动条 500~900px，手型拖动上千 px，稳定性不可接受。

既然要"稳定 + 不卡"，就把控制权拿过来：**我们发滚轮，所以我们知道滚了多少**。

### 一轮的流程

1. 按按钮 → 立即 `TransformInkAsync(0, ∓stepPx×格数)` 平移墨迹（零延迟，跟手）。
   每格像素 `_stepPx` 初始 60（300% 缩放实测），之后按复核结果自学习。
2. 同时 `SendMessageTimeout` 把 `WM_MOUSEWHEEL` 发给 WPS 文档子窗口（`ChildAtPoint` 找到的 `Qt5QWindowIcon`）。
   **发给顶层窗口无效**（实测差异 0.0%）。
3. 等沉降期（`300ms + 40ms×格数`）再抓帧复核。**核心不变量：画面变了就说明页面确实滚了，此时绝不撤回墨迹。**
   一次批量的账本只有两种真相——"滚了 `预期`"或"到边没滚（dy=0）"，所以复核就比这两个假设（同一条带、同一口径）：
   - "停在原地"领先 ≥0.02 → 到顶/到底 → 撤回墨迹（日志 `复核判定没滚(到边)`）；
   - "按预期移动"近乎完美（≥0.93）且领先 ≥0.02 → 滚了 → 按实测结算（日志 `复核确认滚动`）；
   - 分不开 → 信命令，不动墨迹（日志 `复核分不开 → 信命令`）；
   - 批量 >3 拍时先扫 `预期 ± k×格`（k=0,±1,±2）取最像的，扫不到再信命令。
   - 另外，只有"画面完全没变"（预筛 diff < 1.5、连续 2 帧、距按键 ≥900ms）才认定到顶/到底 → 撤回**全额**账本（连按几下就撤几下）。
4. 没有账本的外部滚动（触摸板/拖动滚动条）走自由搜索：只认"几乎确定"的小幅竖向位移，否则只换基线不动墨迹。
   刚按过键 1200ms 内的画面变化算"滚动动画残余"，也只换基线。
5. 补差上限用账本推导：`|补差| > |预期| + 100px` 判坏匹配丢弃，另有 700px 绝对上限。
6. **对账（一轮按键收尾）**：每轮第一次按键时把当前帧克隆成"锚点"（连同那时的墨迹 Y），
   之后每次按键都不动锚点。一轮停手、画面真正静止后，用锚点跟现在这帧比**整轮总位移**，
   再跟这一轮墨迹实际走过的量对齐：差 ≥0.6 格就补，<0.6 格不动（避免把重排抗锯齿当误差），
   单次补差夹在 ±3 格内。这一层专门兜"多格批次只能信命令"的漏账——
   实测 WPS 偶尔会吞掉连按里的一拍，靠逐拍复核发现不了，一整轮比一次才看得出来。
   两道闸门（2026-10-17 补）：①距最后一次按键 <900ms 不下结论（连按时的"停手"常常发生在 WPS 动画起步之前）；
   ②"页面 0px"要 300ms 后再确认一次，两次都是 0 才把墨迹退回去。

### 几个必须踩过的坑（都已修）

- **"没滚"判定把整批乐观平移撤回 → 墨迹反向蹦一大步（用户实际踩到的主 bug）**：
  连按 10 下攒出 `预期=600px`，WPS 实际滚了不等于 600（惯性/被吃掉几格），两个固定假设都对不上，
  而"没滚"的带更容易找 → 判"没滚" → `补差=(0,600)` 把 600px 全撤回 → 手指在按 ↑，墨迹却往上跳一大步。
  日志指纹：`二选一复核: 预期=-780px 滚了=0.306 没滚=0.942 → 判定 没滚` + `JUMP apply dy=0px 补差=(0,600)`。
  → 现在①画面变了就永不撤回；②复核改为"两个假设各用自己最合适的带"（dy=600 时同时容得下 600 和 0 的带只剩页顶空白，
    移动假设必然低分）；③在预期附近扫 ±1/±2 格纠偏；④扫不到就信命令。
- **"静止"被当成"到边"**：按下后 WPS 还没开始动画，一帧静止就撤回，等它真滚了账本已经没了。
  → 要连续 2 帧静止 + 沉降期过后 + **距按键 ≥900ms** 才允许撤回；沉降期按格数放宽。
- **对账抢跑（连按时"永久差一格"的真凶，2026-10-17 修）**：`WpsScroll.Send` 是阻塞的
  `SendMessageTimeout`（实测 130~300ms），而 `_lastPressAt` / `_settleUntil` 原来写在它**后面**。
  于是发消息那段时间里跟随线程仍"以为很久没按键"，拿上一轮锚点下结论、把刚推出去的墨迹按一格退回，
  而 WPS 恰好在之后再开始滚动 → 每发生一次永久错位一格。
  日志指纹：`对账: 墨迹走了 60px，实测页面 0px → 修正 -60px` 之后 60~70ms 才出现 `翻页动画中…`；
  8 次连按里 6 次对账全部落在动画开始之前，而延迟 1.1~1.4s 的 6 轮"对账一致"全对。
  → 时间戳提前到下发之前（但仍在建锚点之后，建锚点要读 `_still`），另加上面两道闸门。
  压测：`Ctrl+Alt+↓`×6 @120ms → 只出现 `对账: …… 与墨迹一致(0.978/0.913) 差 0px 不动`；
  真到顶时 → `对账待确认 … 300ms 后再判` → `对账确认 … 两次都是 0px` → `修正 -120px`。
- **关掉插件后工具栏留一条"很瘦的底儿"（用户报的，2026-10-17 修）**：
  宿主给插件项的容器是 `StackPanel(1) < Border(1) < SimpleStackPanel(5)`，我们把自己的面板
  `Collapsed` 只收掉内容，外面那两层容器仍在，于是留下一条空底壳。
  → 隐藏时顺着可视树往上，只收"独生孩子"的纯包装层（`StackPanel` + `Border`），
  遇到 `SimpleStackPanel(5)`（原生 鼠标/批注/白板/工具/隐藏 的排列区）立刻停手。
  另一个坑：视图 `Loaded` 之后宿主会把 `Visibility` 改回 `Visible`，且 `BuildPanel()` 里
  调 `VisualTreeHelper.GetParent` 全是 null（还没挂树，日志 `可视树: ` 为空）→
  必须在 `Loaded` 里 `Dispatcher.BeginInvoke(ApplyUiMode)` 再压一次，并挂 `IsVisibleChanged` 立刻反弹。
  日志指纹：`工具栏外壳隐藏 2 层: StackPanel < Border` / `工具栏外壳恢复 2 层: StackPanel < Border`。
- **滚动动画残余被当成新滚动**：沉降期后 WPS 还在滑行，那几帧的变化被自由搜索解释成位移 → 墨迹自己乱跑。
  → 按过键 1200ms 内只换基线不动墨迹。
- **外部滚动把墨迹推歪（用户报的"鼠标模式下滚轮/手型/滚动条一动，笔迹整个错位"）**：
  以前没有账本时（不是我们发的翻页）会用自由搜索去追页面，只接受 `Score≥0.95 且领先≥0.03 且 |Dy|≤240`，
  但手型拖动、滚动条拖动都是几百像素的连续变化，匹配出来的位移纯属噪声，墨迹被推到完全错位的位置。
  → 现在这条路径直接删掉：没有账本 = 不是我们下发的滚动 → 只换基线，不动墨迹（`外部滚动，不跟`）。
  日志指纹：滚轮/手型/滚动条期间全是 `status: 外部滚动，不跟`，没有任何 `apply dy=`、`Δ` 不变。
- **"每格像素"被学到 72 而不是 60（用户报的"笔迹与页面像素不同步"）**：
  旧逻辑拿"任何非零实测 dy ÷ 格数"当样本，一次 7 格因为吃到 `dy=504` 就写成 `504/7=72`，
  之后每按一下就多推 12px，按十下偏 120px，越滚越歪。
  → 现在只收**单格 + 强匹配**样本（`Score ≥0.985`、领先次优 ≥0.05），与当前值差 ≤8% 视为没变；
  真要改（用户改缩放）必须**连续两次给出同一个新值**。实测探针独立标定：1 格 = 60px、3 格 = 180px。
- **账本改动史**（两个极端都踩过）：①累加 → 一次误判整批撤回（反向大跳）；
  ②"只记最近一次" → 到顶连按两下时第 1 拍的 60px 永远没人核对（用户报的"连按两下不能归位"，实测差 18.5%）；
  ③"攒够两拍就丢弃" → 连按五下只撤回一拍，剩 240px 白留。
  → 现在**纯累加**：每拍都会被随后的复核消费掉（三条判据里总有一条命中），到边时由"画面完全没变"撤回全额；
  实测到顶连按 2/3/5/8 下，逐点差 **全部 0%**。
- **"按命令结算"当作兜底**：到边时 WPS 自身重绘噪声（diff 11~19）被当成"页面滚了"，账本被吃掉 → 墨迹越按越偏。
  → 兜底只在"两个假设分不开"时才用；噪声大但"停在原地"仍领先时，一律判到边。
- **单格也跑 ±2 格候选扫描**：扫 5 个候选要 200ms，把每次按键的复核窗口挤掉，最后硬生生变成"一批只复核一次"。
  → 单格直接信命令（只保留"页面到底没动"那一条否决权），多格才扫描。
- **到边判据被"动画刚开始"骗过**：按下 100ms 时画面几乎没变，`ScorePair` 会说"没动"→ 整批撤回。
  → 到边判据加三道闸：距按键 ≥900ms、预筛差异 ≤8、`停在原地 ≥0.995 且 按预期移动 ≤0.95`。
- **对账锚点建晚了一拍**：锚点要在"推墨迹之前"记录（`_anchorInkY` 取的是这一拍还没推时的 `_shift.Y`）。
  写在 `ApplyAsync` 之后就会少算一格，于是对账每轮多补一格 → **每轮固定 +86px 的净漂移**（用户报的"往下时笔迹跑错位置"就是这个）。
- **Ctrl 按住时 WPS 把滚轮当缩放**（Ctrl+滚轮 = 缩放）。热键本身就是 Ctrl+Alt+方向键，用户没松手就注入滚轮会让文档突然缩放。
  光"等修饰键抬起"还不够：连按热键时**下一轮**的 Ctrl 会和我们的 `SendMessage` 撞在一起（WPS(Qt) 处理滚轮时读的是"当时"的键状态），
  实测缩放在几轮连按测试里被偷偷改成了 600%/400%/226.65%。
  → 现在要求 Ctrl/Alt/Shift/Win **连续 120ms 都松开**（`WaitModifiersQuiet(120, 900)`）才发；超时就放弃这次按键并撤回墨迹。
  （实测每格位移与缩放无关，都是 60px，所以偶发缩放不会让账本算错，只是画面看起来变了。）
- **`_stepPx` 被一次坏匹配带跑**：原来任何非零实测 dy 都写进"每格像素"，曾把它学到 140px，于是之后每次按键都把墨迹推 140×格数 —— 这就是"突发大幅错位"的主因。
  → 现在只有"实测 ≈ N×当前值（偏差 ≤25%）"才采纳；大跳变（改缩放）要**连续两次一致**才认；范围夹在 30~200px。
- **没有账本时的自由搜索**：光标闪烁/悬浮按钮/重排都会让画面变，那时搜出来的位移纯属噪声（实测出现过一次凭空 +181px、+480px，还有一次横向 -204px）。
  → 无账本只认"几乎确定"的小幅竖向位移（相似度 ≥0.95、领先次优 ≥0.03、|dy| ≤240、dx=0），否则**只换基线不动墨迹**；横向位移一律不跟。
- **补差上限用账本本身推导**：合法补差最多是"把这次乐观平移全撤回"，所以 `|补差| > |预期| + 100px` 直接判为坏匹配丢弃，另有 700px 绝对上限。
- **按下的那一瞬间抓到的帧是"滚之前"的**，用它结算会把正常滚动误判成"到边"。
  → 每次按下 `_gen++`，抓完帧发现 gen 变了就作废这一帧。
- **空白区域任何位移都"很像"**（白对白）→ 二选一必然误判。→ 带内暗像素比例 <3% 时拒答，改按预期结算。
- **`GetClassNameW` 忘了 `CharSet.Unicode`**：Ansi 编组把 UTF-16 类名截成 `"Q\0"`，`StartsWith("Qt5")` 恒假，一直"没找到 WPS 窗口"。
- PowerShell 5.1 读写含中文源码/脚本会按 ANSI 处理而毁掉文件：改源码只用编辑器，`tools/*.ps1` 一律纯 ASCII。

日志**始终开着**（宿主负责落盘，没有开关），一天一个文件，重度测试一天约 100KB / 1000 行，可以放心长期留着。

每行都带足够复盘的字段：

- `press #N 1 格 墨迹(-60) step=60 账本=60px →子窗口 delta=-120 Δ=(0,-60) n=1` —— 按了第 N 下，命令几格，墨迹累计偏置 `Δ`；`账本` 是这一下之后"还没被复核确认"的累计量。
- `#N 复核确认滚动 -60px（1.000/0.832）step=60 diff=22.0` —— 第 N 下被证实滚了，括号里是"移动假设/静止假设"的相似度。

- `#N 复核修正: 命令 -180px → 实测 -240px` / `JUMP apply … 补差=(0,-300)` —— 实测比命令多，已纠偏（`JUMP` 是单次 ≥300px 的告警）。

- `MARK 用户标记 墨迹…` —— 按 `Ctrl+Alt+M` 打点，汇报"这里偏了"时我按它定位。

一键摘要：

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\diag.ps1
```

它统计按了多少下、各类判断多少次、可疑行（JUMP/越界/每格变化/异常）、最近心跳和最后 15 行。

## 已知边界

- **单格（`↑`/`↓`）偶尔会被 WPS 吃掉**：那一下页面没动，若复核也分不开（日志 `复核分不开 → 信命令`），靠收尾的"对账"补回；若对账三次都测不出（页面大片留白/刚好翻到页缝），墨迹会永久差**最多一格**，按一次反向键或 `Ctrl+Alt+R` 归位即可。
- **一批连按超过 ~10 格（600px）时复核不了**：单帧里比较不了这么大的位移，会扫完候选后信命令；WPS 如果少吃/多吃几格，墨迹就会偏几行。
- **只跟我们自己发的滚动**。手指在触摸板上滚、拖右侧滚动条、手型拖动，这些仍靠抓画面复核（能跟但快了自己跟不上，会判"认不准"然后停手不动）。
- **改缩放**（Ctrl+滚轮）后每格像素变了：`_stepPx` 会从复核里自学习回来，但缩放那一瞬间墨迹不会跟着缩放（`Matrix` 带 scale 的缩放跟随没做）。
- 只认 **WPS Writer / WPS PDF**（进程名 wps / wpspdf / wpp / et，窗口类 `Qt5*` 或 `OpusApp`）。其它软件不动。
- **每格像素随缩放和文档类型变**（PDF 300% = 60px，docx 200% ≈ 87px）：`_stepPx` 靠单格强样本自学习（连续两次一致才改），刚换文档/刚改缩放的头一两下可能差一行，之后自动校准。
- 横向平移（`dx`）代码路径在，但 WPS 这版 PDF 视图没有触发横向滚动的操作（`HWHEEL` 不响应），未实测。
- 到文档首/尾时按钮会"空按"：墨迹先跟随动一下再撤回（一次 ~0.5s 的抖动），这是没有滚动条位置可读的代价；**最终位置一定与页面对齐**（实测首/尾各按 50 格以上，截图逐点差 0%）。

## 代码结构

- `WpsInkSync/WpsInkSyncPlugin.cs` — `[PluginEntrance]` 入口：取服务、挂 `PenModeChanged`、浮动栏按钮 + 热键
- `WpsInkSync/WpsFollower.cs` — 主循环：门控 → 抓帧 → 复核（二选一）→ 补差/撤回；以及 `PressAsync`（命令滚动 + 乐观平移）
- `WpsInkSync/WpsScroll.cs` — 找 WPS 窗口（`Qt5*` = PDF 外壳 / `OpusApp` = .doc(x) 外壳）/ 找文档子窗口 / 注入 `WM_MOUSEWHEEL` / 等修饰键抬起
- `WpsInkSync/InkShift.cs` — 调 `TransformInkAsync(Matrix)`，串行化 + 累计位移 + 归位
- `WpsInkSync/WheelTrigger.cs` — `WH_MOUSE_LL` 全局钩子，听到滚轮就把跟随器切到高频态（外部滚动兜底用）
- `WpsInkSync/manifest.json` — 清单（Id `com.yg.wpsinksync`，插件目录名必须等于 Id）
- `tools/ScrollProbe/Capture.cs` — 抓帧 + 匹配算法（插件通过 `<Compile Include>` 复用同一份源码，避免两份实现漂移）
- `tools/ScrollProbe/` — 控制台探针：`dump`（窗口/UIA 侦察）、`probe`（注入滚轮对比）、`shot`（抓帧存 BMP）、`cmp a.bmp b.bmp`（离线量两张截图的位移）
- `tools/hk.ps1` — 用真实按键事件触发 ICC 全局热键（`-Key UP|DOWN|PGUP|PGDN|K|F|R|M`）
- `tools/wheel.ps1` / `tools/seq.ps1` — 真实滚轮注入 / 往返回归（打样 + 上下滚 + 三张截图）
