## v0.2.4 — 插件按钮只在 WPS 的 doc(x)/PDF 标签下出现

### 改了什么

设置里的「仅当 WPS 运行时」改名为 **「仅当 WPS doc(x)/PDF 时」**，语义也改了：

- 以前：只要 WPS 进程还在、有一个可见的 WPS 窗口，插件按钮就一直显示。
- 现在：只有 **当前活动标签** 正在显示 `.docx` / `.doc` / `.pdf` 时才显示按钮、才注册热键、才启动跟随器。

同一个 WPS 里同时开着 PPT(X) 和 docx/PDF 时，看的是当前活动标签：切到 PPT 标签，按钮立刻收起、热键失效；
切回 docx/PDF 标签，按钮和热键自动恢复。只开 PPT/表格时插件完全待机，不再每 400ms 抓帧。

设置项键名没变（`com.yg.wpsinksync.uiMode=wps`），老配置不用改。默认值仍是「始终」，行为不变。

### 顺手修了一个隐藏问题

老代码只认两种顶层窗口类：`Qt5*`（PDF）和 `OpusApp`（docx）。实测发现**从 PPT 启动的 WPS**，顶层窗口类是
`PP12FrameClass`（统一框架），docx/PDF 都挂在这个框架下面 —— 这种 WPS 会被老代码判成「没找到窗口」，
插件完全不工作。

现在不再看顶层类名，改看「子树里有没有正在显示的文档视图」：`OpusApp`/`_WwG` 判 docx，
`Qt5*` 且标题带 `WPS PDF` 或 `.pdf` 判 PDF，最后用顶层标题的扩展名兜底。

### 实测（本机 1920×1080 / 96dpi，WPS 12.1.0.29161，同一窗口开 docx + PDF + PPTX 三个标签）

| 操作 | 结果 |
| --- | --- |
| docx 标签 | 显示、热键可用，6 格稳态 236–325ms（位移 545px，补差 0） |
| 切到 PDF 标签 | 仍显示，尺子自动换成 PDF（`PDF UIA 标尺: 滚动值=539px`），6 格 360px、命中5/5 |
| 切到 PPTX 标签 | **按钮收起、热键失效**（按 PgDn 日志无任何 `press #`），跟随器停止 |
| 切回 docx | 按钮和热键自动恢复，翻页正常 |

### 已知取舍

- 判断依据是「文档视图是否可见」，切标签的一瞬间可能晚 0.5 秒才切换状态（定时器 500ms 探一次）。
- docx 与 PDF 来回切标签后 docx 侧滚动可能僵死，是 WPS 自身问题（重启 WPS 恢复），本版未处理。
